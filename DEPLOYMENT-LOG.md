## Deployment Steps

### Step 1: Environment Preparation
1. Render (or hosting platform) will deploy from this commit: `ee49f83`
2. Required environment variables (auto-configured in render.yaml):
   ```
   NEXA_DEBUG=0                              # Production mode
   NEXA_SECRET_KEY=<auto-generated>          # Render generates this
   NEXA_ALLOWED_HOSTS=api.Nexa-app.com,...   # API domain
   NEXA_CORS_ORIGINS=https://app.Nexa.com    # Frontend URL
   NEXA_FRONTEND_URL=https://app.Nexa.com/   # Magic link base
   NEXA_DATABASE_URL=<postgres>              # From database service
   ```

### Step 2: Database Migration (Automatic)
Render's `startCommand` automatically runs:
```bash
python manage.py migrate --noinput  # Applies 0017 (team sharing schema)
python manage.py createcachetable   # Cache table initialization
gunicorn nexa.wsgi --bind 0.0.0.0:$PORT  # Start server
```

**Migration 0017 Details**:
- Adds `UserSettings.team_sharing_enabled` boolean flag
- Creates `TeamMembership` table (owner, member, permissions JSON, timestamps)
- Creates `TeamInvitation` table (email, token_hash, permissions, expiration, accepted_at)
- Indexes on (owner, member) and (owner, email) for query performance

### Step 3: Health Check
After deployment, verify:
1. API health: `curl https://api.Nexa-app.com/health` → HTTP 200
2. Magic link delivery: Request password reset → Email received
3. Team endpoints accessible: `curl https://api.Nexa-app.com/account/teams/` → Requires auth
4. HTTPS redirect: `curl http://api.Nexa-app.com/` → 301 to HTTPS
5. HSTS header: Response includes `Strict-Transport-Security: max-age=31536000`

## Rollback Plan

If critical issues occur post-deployment:

### Quick Rollback
1. Render dashboard → Trigger a new deploy from previous commit
2. Automatic: Old version deployed, database rollback not needed (migration is additive)

### Rollback Database (if needed)
```bash
# DO NOT run unless migration 0017 caused critical data corruption
# (This should not happen; schema is additive only)
python manage.py migrate api 0016  # Revert to previous state
```

**Note**: Rollback is low-risk because:
- Migration 0017 is purely additive (new tables, no changes to existing ones)
- Existing business data (sales, products, etc.) unaffected
- Team tables just go unused if the feature is disabled

## Feature Flags

Team sharing is controlled by:
1. **Backend**: `UserSettings.team_sharing_enabled` flag (opt-in at registration)
2. **Frontend**: Visible in account settings only when flag is true
3. **Migration**: 0017 creates tables; feature fully baked in

**To disable**: Set `team_sharing_enabled = False` for all users (not recommended; just don't use it).

## Performance Considerations

### Database Queries
- **Team membership lookup**: Indexed on (owner, member) → O(1) lookup
- **Workspace selection**: Indexed on (owner, email) for invitation lookup → O(1)
- **Permission check**: Loaded from TeamMembership.permissions (JSON) → No N+1 queries
- **Member list**: Single query with prefetch_related → O(n) members, not O(n²)

### Caching
- **Workspace context**: Cached in `request.owner` and `request.membership` → No repeated queries
- **Permission set**: Loaded once per request (small JSON) → Minimal overhead
- **Team list**: Frontend caches workspace list → Reduces API calls

### Scaling
- **Free plan**: Supports up to ~1000 team members per business (before hitting Postgres limits)
- **Launch plan**: Supports 10,000+ team members per business
- **Horizontal scaling**: Stateless; add web instances without code changes

## Security Audit Trail

### Vulnerabilities Addressed
- ✅ CSRF via form submission: Bearer token auth prevents browser-based cross-origin requests
- ✅ Session hijacking: HTTPS + secure-only cookies prevent interception
- ✅ Privilege escalation: Non-owners can't delegate permissions they don't have
- ✅ Invitation replay: Single-use tokens with email matching prevent reuse
- ✅ SQL injection: ORM parameterization (all Django queries)
- ✅ Data leakage: Workspace scoping + permission checks before every read
- ✅ Unauthorized access: Bearer token required on every API endpoint

### Security Tests
1. `test_workspace_selection_enforces_permissions_and_never_falls_back` — No fallback to personal workspace
2. `test_team_manager_cannot_grant_permissions_they_do_not_have` — No privilege escalation
3. `test_account_sessions_remain_scoped_to_signed_in_person` — Account data isolated
4. `test_invite_acceptance_keeps_personal_data_separate` — No data leakage
5. `test_disabling_sharing_revokes_members_and_preserves_owner_data` — Revocation works
6. `test_registration_can_enable_team_sharing` — Opt-in works
7. `test_view_only_insights_allow_analysis_without_edit_access` — Permission limits enforced
