🎓 KEY TECHNICAL HIGHLIGHTS
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

1. WORKSPACE CONTEXT RESOLUTION
   • X-Nexa-Workspace header injects workspace ID
   • @api decorator validates membership with required permission
   • Server-side validation prevents header forgery
   • Automatic fallback to personal workspace for workspace=False endpoints

2. PERMISSION NORMALIZATION & ENFORCEMENT
   • Permissions stored as JSON in TeamMembership: {scope: {view, edit}}
   • Edit permission requires view permission (enforced)
   • Non-owner managers cannot delegate permissions they don't have
   • API checks permission before every business operation

3. INVITATION SECURITY MODEL
   • Tokens hashed on storage (bcrypt-style)
   • Preview & accept routes validate token hash and email match
   • Accepted invitations marked with accepted_at timestamp
   • Re-acceptance blocked (replay prevention)
   • 7-day expiration enforced

4. TRANSACTION-LEVEL ATOMICITY
   • Member updates use select_for_update() to prevent race conditions
   • Disabling sharing wrapped in @transaction.atomic
   • All memberships/invitations deleted atomically or not at all

5. FRONTEND PERMISSION-GATED UI
   • canAccess(scope) checks view permission (shows/hides navigation)
   • canEdit(scope) checks edit permission (disables buttons)
   • permission-locked CSS class disables fieldsets without layout change
   • Real-time permission updates on save

6. ACCOUNT ISOLATION
   • Sessions (ApiToken) listed only for signed-in actor (workspace=False)
   • Team members cannot see each other's device list
   • Personal account remains independent of team workspace
   • No data leakage between workspace contexts
